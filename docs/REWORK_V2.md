# MV 重制 v2 —— 从"循环几个画面"到"一句一镜"的改造记录

> 生成时间：2026-10-24
> 对应问题清单：`docs/MV_ISSUES.md`（P01–P12）
> 质量表：`docs/MV_QUALITY_REPORT.md`（`node render_mv_v2.mjs stats` 生成）
> 字幕表：`docs/SUB_TIMING.md`（`tools/merge_timings.py` 生成）

---

## 0. 一句话结论

旧版 14 部 MV 之所以"一直循环几个画面"，根因是**没有镜头引擎**：
每个包都是 `if (t < 20) 画场景A; else if (t < 40) 画场景B …` 的硬编码时间片，
角色在片子里只有 5 个静态姿势；字幕时间是手写的、从没跟音轨核对过。

v2 把这两件事拆成了两层独立系统：

| 层 | 文件 | 作用 |
|:--|:--|:--|
| **字幕时间轴** | `tools/ocr_reference_subs.py` → `tools/merge_timings.py` → `src/timings/<key>.json` | 时间来自参考片实测，文本来自人工歌词表 |
| **镜头/动作/布景调度** | `src/shotlib.js` + `src/mv_packs_v2.js` | 一句歌词 = 1~3 个镜头，每个镜头独立选布景/动作/机位/时辰 |
| **动作库** | `src/actions.js` | 37 个完整身体动作（呼吸/走路/跳/舞/哭/吃/打瞌睡…） |
| **布景库** | `src/sets.js` | 21 个参数化布景（seed / pan / mood 可换） |
| **细节层** | `src/detail.js` | 空气层（光柱/花瓣/萤火/气泡/雨雪/尘埃）+ 前景遮挡 + 暗角 |
| **统一渲染器** | `render_mv_v2.mjs` | `all \| one <key> \| sheet <key\|all> \| check <key> \| stats` |
| **工作台** | `studio_v2.html` + `tools/serve_studio.mjs` | 浏览器里播放任意一部、逐个回放 37 个动作 / 21 个布景、查看分镜表 |

## 1. 字幕：文本和时间为啥要分开取

参考片的字幕**不能直接当歌词**：里面有错别字、水印（`Agent人生之旅`）、
终端 UI 文案、章节标签，长片还会把整句话 OCR 成一坨。
参考片的时间**比手写表可信**：它是跟着人声打的。

所以：

1. `tools/legacy_timings.mjs` —— 把老模块里**人工写的字幕表**（文本正确）导出到
   `src/timings/legacy/<key>.json`，同时用一组规则剔掉标题卡/旁白
   （以 `>` 开头、以 `。` 结尾、首尾的"歌名 · 副标题"卡、超过 9 秒的排版卡）。
2. `tools/ocr_reference_subs.py` —— 参考片逐帧 OCR 出**每一句字幕出现/消失的时刻**，
   写入 `src/timings/ocr/<key>.json`（短片 2fps、长片 1fps）。
3. `tools/merge_timings.py` —— 用单调 DP 把"正确的歌词行"对齐到"实测字幕段"：
   - 跳过一段 OCR 罚 0.30（允许间奏/UI 文案）
   - 跳过一行歌词罚 0.75（允许 OCR 漏识，交给插值）
   - 匹配代价 = `(1 - SequenceMatcher 相似度) × 2`
   - 未匹配的行在相邻锚点之间**按字数加权**插值
   - **OCR 质量闸门**：清洗后段数 < 歌词行数 × 0.4 → 判定 OCR 无效，退回人工时间轴

实测命中率（`docs/SUB_TIMING.md` 有逐行明细）：

| 影片 | 直接命中 | 影片 | 直接命中 |
|:--|--:|:--|--:|
| `feng` | 38/38 | `jimo_yanhuo` | 18/18 |
| `xinqiang` | 6/6 | `meiguihua` | 60/77 |
| `qunian_xiatian` | 22/26 | `suyan` | 52/57 |
| `ba_huiyi_56` | 15/17 | `huainvhai` | 40/56 |
| `douyin_6` | 5/6 | `ribuluo` | 4/11（参考片字幕是长句叠显，OCR 只能抓到句尾） |
| `lianai_ing` | OCR 证据不足 → 人工时间轴 +2.2s 平移 | `pengyou_de_jiu` / `chaoxi` | 无参考片 → 人工时间轴 |

> 判定规则（`merge_timings.py`）：命中行数 < 3 或平均相似度 < 0.6 → 认为 OCR 里
> 基本没有歌词，改用**人工时间底稿整体平移**（平移量用行的中点差估，
> `lianai_ing +0.95s`、`ribuluo +3.38s`）。这样既保住人工表的句间空隙，
> 又能被参考片校正整体偏移。

> **踩过的坑**：`tools/align_lyrics_audio.py`（纯音频 RMS 包络 + DP）在 `xinqiang`
> 上把人声连续段均分成 13 行 2.62s 的均匀网格 —— 人声没有停顿，能量包络里没有信息。
> 这个工具只作为"OCR 完全不可用"时的兜底，不要当主路径。

## 2. 镜头引擎：一句歌词怎么变成 1~3 个镜头

`SHOT.plan(key, lines, opts)`：

- **机位** = 运动预置（`static / pushIn / pullOut / panRight / panLeft / tiltUp /
  tiltDown / orbit / dutch / drift`）× 景别。
- **景别** `wide / medium / hero / close` 各自带 `u`（角色尺寸）、`zoom`、`focus`（对焦点），
  相机中心由"人物对焦点 + 缩放补偿"算出，保证**特写不会切掉脑袋、全景不会一片空地**。
- **一镜多段**：>2.8s 的句子切两镜（表演 + 特写反应），>7.2s 再切一个环境空镜。
- **空镜填空档**：前奏/间奏/OCR 空档按 ≤4s 切成无字幕空镜，
  保证 **0 秒到结尾一直是动着的画面**（旧版会在这段卡住同一帧）。
- **不重复**：
  - 布景/动作都用"最少使用优先"（LRU）+ 最近 N 个禁用，
    不再是 `i*7 % n` 这种跟长度不互质、4 个一循环的取法；
  - **时辰轮转**（`MOOD_CYCLE`）：同一布景在不同镜头换 `night/dusk/sunny/dawn/rain` 调色，
    配合每镜头不同的 `seed`（换布局）和 `pan`（换视差位），重复布景也不再是同一张画；
  - 帽子 6 种轮换、配角隔镜头出场、`view` 在 `front`/`q` 之间交替。

## 3. 细节层（解决"像一张平贴纸"）

`src/detail.js` 按布景名自动派发素材，21 个布景直接获得纵深：

| 布景类型 | 空气层 | 前景层 |
|:--|:--|:--|
| 深海 / 海滩 / 泳池 / 银河 | 上浮气泡 + 月光光柱 | 水面波纹 + 压暗 |
| 烟火 / 舞台 | 上升火星（加法混合） | 人群剪影 |
| 秋天公园 / 山坡 / 温室 | 飘落花瓣 | 草叶（渐变、圆头，不做尖刺） |
| 雪街 / 雨站台 | 雨丝 / 雪点 | 栏杆 |
| 教室 / 图书馆 / 咖啡馆 / 车厢 / 卧室 | 漂浮尘埃 + 窗光 | 细窗框（不是黑边） |

外加统一暗角，让主体更亮。

## 5. 怎么复核

```bash
# 1. 重新生成字幕时间轴（可选，已提交结果）
/tmp/ocrenv/bin/python tools/ocr_reference_subs.py all   # 需要 RapidOCR 环境
/tmp/ocrenv/bin/python tools/merge_timings.py all

# 2. 看统计
node render_mv_v2.mjs stats        # → docs/MV_QUALITY_REPORT.md

# 3. 重新出片 + 分镜图
node render_mv_v2.mjs all          # → mv_<key>_whale_girl.mp4 + docs/storyboard_<key>.png
node render_mv_v2.mjs one xinqiang
node render_mv_v2.mjs check xinqiang   # → docs/subcheck_xinqiang.png（与参考片同秒对拍）

# 4. 人工看片（浏览器工作台）
node tools/serve_studio.mjs 4173   # → http://localhost:4173/studio_v2.html
```

工作台里可以：
- 任意一部 MV 拖时间轴逐帧看（字幕、动作、机位、布景都可实时核对）；
- 37 个动作逐个单帧回放（含分类筛选：待机/移动/身体/表情/生活）；
- 21 个布景逐个查看；
- 任意一部片子的分镜表（每个镜头一张缩略图 + 时间/布景/动作标签）。

## 6. 仍然存在的已知问题

1. **像素骨骼黑矩形**：`wink` / `panic` / `heart` 三个姿势附近，手臂骨骼旋转后会露出
   一个黑色矩形（`src/whale_girl.js` 的骨骼绘制没有裁剪到角色轮廓内）。已定位，未修。
2. **`ba_huiyi_pinhao` 的 OCR 不可用**：参考片就是我们自己上一版的输出，画面里的章节标签
   会让 OCR 把整段粘成一块，因此该片用人工时间轴（列表里仍标注 `legacy-handwritten`）。
3. **`chaoxi` / `pengyou_de_jiu` 没有参考片**：无法 OCR 校验，字幕时间仍来自人工表
   （已用空镜补满空隙，至少不会再"卡住同一帧"）。
4. **长片帧率 12fps**：为了控制渲染时间（4 部长片合计约 1000s），长片用 12fps
   + 手绘 boil，短片 15fps。
